# T04.1 — Installation plug-in Prompt Search en moins d'une heure

> Permet à l'administrateur d'une boutique en ligne tierce d'ajouter la recherche par prompt Magrit à son site en moins d'une heure, pour l'essayer sans engagement technique lourd.

## Valeur métier

Prompt Search ne se vend pas, il s'essaie. Un imprimeur qui doit mobiliser une agence pour intégrer un champ de recherche ne le fera pas : il reportera, puis renoncera. L'heure d'installation n'est pas une performance technique, c'est le seuil en dessous duquel un administrateur accepte de tester sans demander d'autorisation ni de budget. C'est la porte d'entrée de toute l'epic : aucune des stories suivantes n'a de valeur si le plug-in n'est pas posé.

## Besoin utilisateur

**En tant qu'**administrateur d'une boutique Shopify, WooCommerce, Magento ou BigCommerce, **je veux** installer le plug-in Magrit Prompt en moins d'une heure de configuration, **afin de** le tester sans engagement lourd.

## Comportement attendu

1. L'installation se fait par la place de marché de la plateforme quand elle existe, ou par insertion d'un extrait de code pour Magento et les intégrations WooCommerce sur mesure.
2. La configuration initiale demande : la clé d'accès Magrit, la position du champ dans l'en-tête du site, et le texte d'invite affiché dans le champ.
3. Si le connecteur de l'epic T-03 est déjà opérationnel pour cette boutique, le plug-in est actif immédiatement après configuration.
4. L'administrateur choisit le mode de fonctionnement : « prompt uniquement » ou « prompt avec repli sur la recherche classique ».
5. Des surcharges de style permettent d'aligner l'apparence du champ sur le thème de la boutique.

## Expérience utilisateur

- La configuration tient en trois décisions, pas en un écran de réglages : clé, emplacement, texte d'invite.
- L'administrateur doit pouvoir constater que ça marche sans publier : **la source ne prévoit pourtant ni prévisualisation, ni environnement de test, ni vérification de la clé**.
- Le champ installé doit ressembler au site qui l'accueille, pas à un corps étranger — d'où les surcharges de style.
- **La source est muette** sur : le message affiché quand la clé est invalide, l'état du champ quand le connecteur T-03 n'est pas opérationnel, la désinstallation, et la mise à jour du plug-in.

## Règles métier

- `RM-01` — L'installation est possible sur Shopify, WooCommerce, Magento et BigCommerce : par la place de marché de la plateforme quand elle existe, par extrait de code sinon.
- `RM-02` — La configuration minimale se limite à trois paramètres : clé d'accès, position du champ, texte d'invite.
- `RM-03` — Le plug-in n'est actif que si le connecteur T-03 de la boutique est opérationnel. À défaut, l'administrateur doit le savoir.
- `RM-04` — Le mode de fonctionnement — « prompt uniquement » ou « prompt avec repli recherche » — est un choix de l'administrateur, modifiable après installation.
- `RM-05` — L'apparence du champ est surchargeable pour s'aligner sur le thème de la boutique, sans modification du code du plug-in.
- `RM-06` — La clé d'accès identifie le tenant Magrit de la boutique ; elle conditionne l'accès au catalogue de ce tenant et d'aucun autre.
- `RM-07` — Le parcours complet, de l'installation à un premier prompt fonctionnel, tient en moins d'une heure pour un administrateur de boutique sans assistance.

## Critères d'acceptation

- `AC-01` — Étant donné une boutique sur chacune des quatre plateformes citées, quand un administrateur suit la procédure documentée, alors le champ de recherche par prompt est visible sur la boutique.
- `AC-02` — Étant donné une installation neuve, quand on chronomètre le parcours complet d'un administrateur non assisté, alors il tient en moins d'une heure.
- `AC-03` — Étant donné une configuration achevée et un connecteur T-03 opérationnel, quand l'administrateur termine, alors le champ répond à une première requête sans étape supplémentaire.
- `AC-04` — Étant donné une clé d'accès invalide, quand l'administrateur valide la configuration, alors il en est informé avant la mise en ligne du champ (**le message n'est pas spécifié dans la source**).
- `AC-05` — Étant donné le mode « prompt uniquement », quand une requête ne produit aucun résultat de prompt, alors aucune recherche classique n'est déclenchée ; et inversement en mode « prompt avec repli ».
- `AC-06` — Étant donné des surcharges de style appliquées, quand le champ s'affiche, alors il adopte la typographie et les couleurs du thème de la boutique.
- `AC-07` — Étant donné une clé rattachée à un tenant, quand une requête est émise, alors seules les données de ce tenant sont mobilisées (`RM-06`).

## Cas limites

- **Rien n'existe dans le dépôt pour cette story.** Aucun plug-in, widget embarquable ou extrait d'intégration tierce n'est présent dans `src/`. Le seul champ de recherche existant est celui de la boutique Magrit elle-même (`src/modules/catalog/ui/storefront/ShopHeaderSearch.tsx`), qui n'est pas embarquable chez un tiers.
- **Connecteur T-03 absent ou en panne.** Le plug-in est installé mais sans catalogue à interroger. La source ne dit pas si l'administrateur peut installer avant, ni ce que voit l'acheteur dans cet intervalle.
- **Thème de boutique incompatible.** Les surcharges de style ont une limite ; aucune exigence minimale d'intégration n'est posée.
- **Clé compromise ou partagée.** Un extrait de code public contient la clé côté navigateur. La source ne distingue pas clé publique et secret, ni ne prévoit de rotation.
- **Deux champs de recherche.** En mode « prompt avec repli », la boutique peut se retrouver avec le champ natif et le champ Magrit. La source ne dit pas lequel l'emporte — et `PD-2026-10-01-B1`, qui pose une barre unique, rend la question plus aiguë.
- **Mise à jour du plug-in.** Aucune exigence de compatibilité ascendante ni de notification de version.
