# T08.N4 — Mapping de colonnes sémantique (auto + profil par donneur d'ordre)

> Quatrième maillon de la chaîne d'appel d'offres : permet à un imprimeur qui reçoit des bordereaux de mises en page toutes différentes de ne jamais reconfigurer Magrit, parce que le moteur devine le rôle de chaque colonne et mémorise un profil par donneur d'ordre.

## Valeur métier

C'est la story qui décide si le produit tient à l'échelle. Si le rôle des colonnes doit être redéclaré à chaque appel d'offres, la chaîne n'est qu'un script jetable ; s'il est deviné puis mémorisé par émetteur, Magrit devient utilisable sur n'importe quel bordereau. La source le formule comme un principe d'architecture produit : le bordereau du Groupe ICI est **un exemple répétable parmi d'autres** — même hiérarchie métier, particularités propres. Toute logique propre à un émetteur vit dans un **profil**, jamais dans le code. *Ajouter un émetteur = créer un profil, sans modifier le moteur.* La source la désigne comme la story la plus risquée du lot.

## Besoin utilisateur

**En tant qu'**imprimeur recevant des bordereaux de mises en page variées, **je veux** que Magrit identifie automatiquement le rôle de chaque colonne, avec un profil mémorisable par donneur d'ordre, **afin de** ne pas reconfigurer à chaque appel d'offres.

## Entrées et sorties

- **Reçoit** : de `T08.N2`, les lignes typées, dont les lignes produit ; de `T08.N3`, les valeurs héritées résolues ; éventuellement un profil de mapping existant pour ce donneur d'ordre.
- **Produit** : une correspondance rôle métier → colonne du fichier ; un score de confiance par colonne ; les colonnes non résolues, remontées pour arbitrage ; un profil persistable et réapplicable.
- **Alimente** : les quatre normaliseurs `T08.N5` (quantités), `T08.N6` (formats), `T08.N7` (support), `T08.N8` (façonnage), qui dépendent tous de cette story — et, en retour, `T08.N2`, dont les règles de détection sont portées par le profil.
- **Position dans la chaîne** : `T08.N2`, `T08.N3` → **`T08.N4`** → `T08.N5`, `T08.N6`, `T08.N7`, `T08.N8`.

## Comportement attendu

1. Magrit identifie le rôle de chaque colonne par deux voies : les libellés d'en-tête, et les motifs présents dans le contenu des cellules.
2. Les motifs de contenu retenus par la source sont explicites :
   - `\d+\s?ex` → **quantité** ;
   - `RESPECTA|Offset|vinyle|Dibond|Akilux|PVC|bâche` → **support** ;
   - `pli|piqûre|rainage|œillet|découpe|lamination|vernis` → **façonnage** ;
   - `\d+\s?[x×]\s?\d+|Diamètre|Format (fini|ouvert|fermé)` → **format**.
3. Une colonne dont le score reste sous le seuil est remontée pour arbitrage humain (`T08.N14`) sans interrompre le traitement.
4. Pour les libellés exotiques, un modèle de langage sert de repli, avec une sortie JSON contrainte.
5. Une correspondance validée est enregistrée comme profil et réappliquée automatiquement au même donneur d'ordre.

## Expérience utilisateur

- La correction d'une colonne mal devinée et la gestion des profils supposent un écran. **La source ne le décrit pas** : elle renvoie l'arbitrage à `T08.N14` (revue humaine) et cite un ensemble d'opérations de gestion des profils, sans dire qui les utilise ni où.
- Le point d'expérience structurant est que l'utilisateur n'est **jamais bloqué** : une colonne non résolue est signalée, le reste de la chaîne continue.

## Règles métier

- `RM-01` — Le rôle d'une colonne est déduit de deux sources : son libellé d'en-tête et les motifs présents dans son contenu.
- `RM-02` — Les motifs de contenu listés au point 2 du comportement attendu font partie de la spécification : ils ne sont pas des exemples.
- `RM-03` — Chaque colonne reçoit un score de confiance ; sous le seuil, elle est remontée pour arbitrage humain et le traitement se poursuit.
- `RM-04` — Aucune logique propre à un émetteur ne vit dans le code : elle vit dans un profil. Ajouter un émetteur consiste à créer un profil.
- `RM-05` — Un profil validé est persistable et réappliqué automatiquement au même donneur d'ordre.
- `RM-06` — Le recours à un modèle de langage est un **repli**, pas la voie principale ; sa sortie est contrainte au format JSON attendu.

## Critères d'acceptation

- `AC-01` — Étant donné la fixture, quand le mapping s'exécute sans profil et sans intervention, alors les **8 colonnes** sont correctement associées avec un score **≥ 0,9**.
- `AC-02` — Étant donné une colonne contenant `3000 ex.`, quand le mapping s'exécute, alors elle est identifiée comme colonne de quantité, même si son en-tête ne le dit pas.
- `AC-03` — Étant donné une colonne contenant `Dibond 3 mm` et `Bâche 270 g/m²`, quand le mapping s'exécute, alors elle est identifiée comme colonne de support.
- `AC-04` — Étant donné une colonne contenant `2 piqûres à cheval` et `rainage`, quand le mapping s'exécute, alors elle est identifiée comme colonne de façonnage.
- `AC-05` — Étant donné une colonne contenant `210×297` et `Diamètre : 40`, quand le mapping s'exécute, alors elle est identifiée comme colonne de format.
- `AC-06` — Étant donné une colonne dont le score reste sous le seuil, quand le mapping s'exécute, alors elle est remontée pour arbitrage et les autres colonnes sont tout de même traitées.
- `AC-07` — Étant donné un profil validé pour un donneur d'ordre, quand un nouveau bordereau du même donneur d'ordre est ingéré, alors le profil est réappliqué sans intervention.
- `AC-08` — Étant donné un bordereau d'un émetteur inconnu dont la mise en page diffère de la fixture, quand le mapping s'exécute, alors il aboutit ou remonte des arbitrages, **sans qu'aucune ligne de code spécifique à cet émetteur ait été écrite**.

## Cas limites

- **Boucle avec `T08.N2`.** Le typage des lignes suppose la colonne Objet et la colonne quantité connues ; le mapping suppose les lignes produit typées. Les deux stories se déclarent mutuellement en amont. Il manque vraisemblablement une passe de repérage préalable — la source ne la décrit pas.
- **Seuil non chiffré.** `AC-01` fixe un score cible de 0,9 pour la fixture, mais le **seuil de déclenchement de l'arbitrage** n'est pas donné. Sans lui, `RM-03` n'est pas implémentable.
- **Deux colonnes pour le même rôle** — deux colonnes de quantité (principale et supplémentaire), ce que la fixture contient puisque `T08.N5` parle de quantité supplémentaire. La source n'explique pas comment les distinguer.
- **Colonne mixte.** Une colonne « Descriptif » contenant à la fois le format, le support et le façonnage : les motifs des quatre rôles y matchent simultanément.
- **Repli par modèle de langage.** Coût, latence, reproductibilité, comportement hors ligne : rien n'est spécifié. Un mapping non déterministe rejoue différemment d'un import à l'autre, ce qui contredit l'exigence d'idempotence de `T08.N9`.
- **Recouvrement avec `T08.B2`.** Le sous-module catalogue décrit la même mécanique (détection auto, correction, profils réutilisables) en moins précis. Deux moteurs de mapping seraient une erreur.

## Hors périmètre

- L'écran d'arbitrage lui-même (`T08.N14`).
