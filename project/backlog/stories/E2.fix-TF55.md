# E2.fix-TF55 — La boutique ne s'affiche pas en mode sombre par défaut

> Fait en sorte que la boutique B2B s'ouvre dans le thème sombre validé, sans que le visiteur ait à le demander.

## Valeur métier

Le mode sombre n'est pas une préférence d'affichage ici : c'est le rendu sur lequel la boutique a été dessinée et validée. Quand il ne s'applique pas, la boutique s'ouvre dans un thème qui n'a jamais été relu — contrastes non vérifiés, couleurs de marque posées sur un fond qui n'était pas prévu pour elles. Ce que cela coûtait : une boutique montrée à un client dans un état qui n'est pas celui qu'on lui a vendu.

## Défaut constaté

Campagne de tests du 11/05/2026, boutique pilote, affichage 1440 × 900. Aucun attribut de thème n'était posé : ni sur la racine du document, ni sur le corps de page, ni sur le conteneur de la boutique. Aucun élément de la page ne portait le marqueur de thème sombre, et aucune classe équivalente n'était présente. Les fonds calculés étaient clairs — blanc sur le corps de page, gris très clair sur le conteneur de boutique : la boutique s'affichait en mode clair.

Tous les autres critères du cas de test étaient satisfaits : conteneur de boutique présent, en-tête collant aux couleurs du tenant, navigation locale, accès au panier, menu utilisateur, pilules de gammes, et variables de couleurs de marque correctement injectées.

Le cas était classé en priorité la plus haute, parce que le mode sombre est le comportement par défaut attendu de la boutique B2B, et non un réglage offert au visiteur.

## Besoin utilisateur

**En tant que** visiteur non authentifié, **je veux** que la boutique s'affiche en mode sombre par défaut, **afin de** bénéficier du rendu validé et cohérent avec les couleurs du tenant.

## Comportement attendu

1. À l'ouverture d'une boutique active, le thème sombre est appliqué sans action du visiteur.
2. Les fonds et les textes se résolvent sur les valeurs sombres du jeu de couleurs.
3. Les couleurs de marque du tenant restent injectées et visibles en mode sombre : en-tête, visuels, pastilles.
4. Le mode sombre est le comportement par défaut de la boutique B2B, pas une bascule offerte au visiteur.

## Expérience utilisateur

- Le visiteur n'a rien à régler et ne voit pas la page basculer : elle s'affiche d'emblée dans le bon thème.
- Les couleurs de marque gardent leur fonction en mode sombre : elles distinguent, elles ne se fondent pas dans le fond.
- Le parcours clavier reste lisible : l'anneau de focus doit rester visible sur fond sombre.
- **La source est muette** sur la prise en compte d'une préférence système du visiteur pour le thème clair.

## Règles métier

- `RM-01` — Le mode sombre est le comportement par défaut de la boutique B2B.
- `RM-02` — Le mode sombre n'est pas une bascule offerte au visiteur.
- `RM-03` — Les couleurs de marque du tenant restent injectées et visibles en mode sombre.
- `RM-04` — Les éléments interactifs restent repérables au clavier en mode sombre.
- `RM-05` — L'application du mode sombre ne modifie aucun comportement fonctionnel de la boutique.

## Critères d'acceptation

- `AC-01` — Étant donné l'adresse d'une boutique active, quand la page est affichée, alors le conteneur de boutique porte le thème sombre.
- `AC-02` — Étant donné le mode sombre appliqué, quand on examine les couleurs calculées, alors le corps de page et le conteneur de boutique se résolvent sur des couleurs sombres issues du jeu de couleurs.
- `AC-03` — Étant donné un tenant dont les couleurs de marque sont configurées, quand la boutique s'affiche en mode sombre, alors ces couleurs restent injectées et visibles sur l'en-tête, les visuels et les pastilles.
- `AC-04` — Étant donné le mode sombre appliqué, quand le visiteur parcourt les éléments interactifs au clavier, alors un anneau de focus de 2 px à la couleur d'accentuation est visible sur chacun.
- `AC-05` — Étant donné le mode sombre appliqué, quand on vérifie le contrôle d'accès à la boutique, le filtrage par pilules de gammes et l'ouverture du tiroir panier, alors leur comportement est inchangé.

## Cas limites

- **Le défaut est corrigé dans le dépôt.** La boutique résout aujourd'hui son thème avec le mode sombre comme valeur par défaut, et le pose sur le conteneur de boutique. Cette story est **caduque comme travail à faire** ; elle vaut comme exigence de non-régression. Le statut de livraison doit être réexaminé sur preuve, hors de cette passe.
- **Le code laisse une boutique repasser en clair.** Le thème sombre s'applique sauf si le tenant a explicitement configuré sa boutique en mode clair. `RM-02` dit que le mode sombre n'est pas une bascule **du visiteur** ; il ne dit pas si c'en est une pour le tenant. L'écart entre la règle écrite et le comportement livré n'est pas tranché.
- **Boutiques créées avant la bascule.** Une boutique dont le thème a été enregistré en clair reste en clair. La source ne dit pas si ces boutiques doivent être reprises.
- **Préférence système du visiteur.** Un visiteur qui demande le thème clair au niveau de son système n'est pas prévu par la source.
- **Contraste.** La source demande des couleurs « conformes aux jetons » sans fixer de rapport de contraste minimal ni de référentiel. Le critère n'est donc pas mesurable en l'état.

## Hors périmètre

- Les réserves d'accessibilité sur les pilules de gammes et le tiroir panier (`E_A11Y.shop-pills-and-drawer`).
