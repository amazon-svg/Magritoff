# Comptes rendus

Les comptes rendus conservent la chronologie des échanges et servent d'entrée aux artefacts canoniques. Ils ne remplacent ni une décision enregistrée, ni une story approuvée.

## Cycle de vie

1. créer le compte rendu à partir de `_template.md` ;
2. enregistrer décisions, questions et actions ;
3. renseigner la matrice de propagation ;
4. mettre à jour les PRD, décisions, epics, fonctionnalités, stories et tests concernés ;
5. passer `propagationStatus` à `complete` lorsque chaque ligne est traitée.

Les rapports produits par les agents au sujet d'une réunion ou d'une migration sont placés dans `reports/`. Ils restent des preuves de travail, pas des sources normatives.
